Conclusion: **No public API provides the exact CGS-style, window-level desktop blur with independently caller-controlled blur radius plus tint/opacity**. Public APIs provide approximations.

- **NSVisualEffectView — macOS 15 and 26:** `.behindWindow` publicly blurs content behind the window, including the desktop and other windows; `.underWindowBackground` is intended for this use, but it is still a system-selected material—not an untinted/plain blur with configurable radius. [NSVisualEffectView](https://developer.apple.com/documentation/appkit/nsvisualeffectview), [behindWindow](https://developer.apple.com/documentation/appkit/nsvisualeffectview/blendingmode-swift.enum/behindwindow), [underWindowBackground](https://developer.apple.com/documentation/appkit/nsvisualeffectview/material-swift.enum/underwindowbackground?changes=latest_major)

- **NSVisualEffectView tint/opacity — macOS 15 and 26:** There is no documented tint or blur-opacity property; `alphaValue` can fade the entire effect view, while a normal translucent sibling/subview placed above it can tint the already-blurred result through ordinary compositing, but this does not expose the underlying blur strength. [NSVisualEffectView properties](https://developer.apple.com/documentation/appkit/nsvisualeffectview), [NSView alphaValue](https://developer.apple.com/documentation/appkit/nsview/alphaValue)

- **Tint-layer ordering — macOS 15 and 26:** A tint sibling/subview above a `.behindWindow` effect view composites over it; a layer below it becomes part of the effect’s input rather than a guaranteed post-blur tint. Apple notes that overlapping visual-effect views are resolved by hierarchy, with the lower view “winning.” [Apple’s blending-mode documentation](https://developer.apple.com/documentation/appkit/nsvisualeffectview/blendingmode-swift.enum/behindwindow)

- **SwiftUI `.glassEffect` — macOS 26 only:** `.glassEffect(.regular.tint(...))` and `.glassEffect(.clear)` are public and support a tint color, but no documented opacity or blur-radius control; `.clear` is a glass variant, not a plain adjustable desktop blur. [Glass](https://developer.apple.com/documentation/swiftui/glass?changes=_7), [glassEffect](https://developer.apple.com/documentation/swiftui/view/glasseffect%28_%3Ain%3A%29), [clear](https://developer.apple.com/documentation/swiftui/glass/clear?changes=lat_5)

- **Whole-window SwiftUI glass — macOS 26 only:** You can apply `.glassEffect(..., in: Rectangle())` to a root view sized to the window, but the API is view/shape-bounded; Apple does not document it as a window-server desktop-backdrop API or provide an adjustable whole-window blur-opacity control. [Applying Liquid Glass to custom views](https://developer.apple.com/documentation/SwiftUI/Applying-Liquid-Glass-to-custom-views)

- **`GlassEffectContainer` — macOS 26 only:** It combines and morphs descendant Liquid Glass shapes for performance and interaction; it does not turn the window into a caller-controlled desktop blur surface. [GlassEffectContainer](https://developer.apple.com/documentation/swiftui/glasseffectcontainer)

- **`NSGlassEffectView` — macOS 26 only:** It is public AppKit API and exposes `style`, `cornerRadius`, `contentView`, and `tintColor`; it has no documented opacity, blur-radius, or “plain/no-material” control, so `tintColor` is adjustable tint but not CGS-equivalent control. [NSGlassEffectView](https://developer.apple.com/documentation/appkit/nsglasseffectview), [tintColor](https://developer.apple.com/documentation/appkit/nsglasseffectview/tintcolor?changes=_5)

- **`CALayer.backgroundFilters` / Gaussian blur — macOS 15 and 26:** This is public and filters content immediately behind the layer, normally content in its superlayer; it does not access or blur pixels behind the application’s window, so it cannot reproduce desktop blur. [backgroundFilters](https://developer.apple.com/documentation/quartzcore/calayer/backgroundfilters?changes=la)

- **App Store Review Guideline 2.5.1:** Apple states that apps may use only public APIs and must run on the currently shipping OS; `CGSSetWindowBackgroundBlurRadius` is a private CoreGraphics/SkyLight API and therefore violates that rule for App Store distribution. [Apple App Review Guidelines §2.5.1](https://developer.apple.com/app-store/review/guidelines/)

- **Has `CGSSetWindowBackgroundBlurRadius` been rejected?** Yes, there are reported Mac App Store rejections specifically because binaries linked against private CGS APIs including `CGSSetWindowBackgroundBlurRadius`; this is third-party evidence rather than an Apple-published case record. [Zed/GPUI report](https://github.com/zed-industries/zed/discussions/52614), [historical developer report](https://forum.xojo.com/t/translucent-window-with-blur/22283/5)

**Practical answer:** use `.behindWindow` plus an above-effect translucent tint layer for macOS 15/26; use `NSGlassEffectView.tintColor` on macOS 26 if Liquid Glass is acceptable. Neither exposes a public CGS-like blur-radius/opacity API.
