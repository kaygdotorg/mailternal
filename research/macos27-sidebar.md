macOS 27 (“Golden Gate”) does exist: Apple announced it at WWDC26, and public developer documentation/betas are available.

- **Appearance change:** macOS 27 sidebars become edge-to-edge instead of Tahoe’s floating, inset panels; content still flows behind them, sidebar selection uses semibold text, and sidebar icons regain accent-colored rendering. [WWDC26 Platforms State of the Union](https://developer.apple.com/videos/play/wwdc2026/102/), [Modernize your AppKit app](https://developer.apple.com/videos/play/wwdc2026/289/)
- **Other related changes:** Liquid Glass is tuned for readability with stronger diffusion, darker edges, brighter highlights, tighter window corners, and more consistent toolbar treatment. [WWDC26 Platforms State of the Union](https://developer.apple.com/videos/play/wwdc2026/102/)
- **SwiftUI:** `navigationSplitViewStyle(_:)` controls split-view interaction/layout behavior (`balanced`, `prominentDetail`, or automatic); it is not a public switch between Tahoe and macOS 27 sidebar chrome. [NavigationSplitViewStyle](https://developer.apple.com/documentation/swiftui/navigationsplitviewstyle)
- **AppKit:** `NSSplitViewItem` exposes pane behavior, sizing, collapsing, full-height layout, and title-bar separator configuration, but no public “floating Tahoe sidebar” versus “edge-to-edge macOS 27 sidebar” selector. [NSSplitViewItem](https://developer.apple.com/documentation/appkit/nssplitviewitem)
- **Automatic adoption:** Standard SwiftUI/UIKit/AppKit components adopt the current platform’s design automatically; Apple describes the 2027 appearance as automatic rather than opt-in. [Adopting Liquid Glass](https://developer.apple.com/documentation/TechnologyOverviews/adopting-liquid-glass), [WWDC26 What’s new in SwiftUI](https://developer.apple.com/videos/play/wwdc2026/269/)
- **`UIDesignRequiresCompatibility`:** This key is not a runtime/user-selectable sidebar-style API; Apple says it is ignored when the app is built with the Xcode 27 SDK, while an Xcode 26-built app can use it as an app-wide compatibility mode on macOS 26/27. [Apple documentation](https://developer.apple.com/documentation/bundleresources/information-property-list/uidesignrequirescompatibility), [Apple DTS clarification](https://developer.apple.com/forums/thread/838637)
- **Old style on macOS 27:** An Xcode 26-built binary with `UIDesignRequiresCompatibility=YES` may preserve the older design, but this is a static compatibility mechanism, not a supported per-user or per-sidebar choice; Apple is removing the old-design opt-in for Xcode 27-built apps. [WWDC26 Platforms State of the Union](https://developer.apple.com/videos/play/wwdc2026/102/)
- **macOS 27 style on macOS 26:** No public API promises that the macOS 27 sidebar appearance can be backported to macOS 26; the documented model is that standard controls resolve their appearance from the running OS. A custom sidebar can approximate either look, but would not be the system sidebar style. [Adopting Liquid Glass](https://developer.apple.com/documentation/TechnologyOverviews/adopting-liquid-glass)
- **Supporting both:** Apple’s public guidance is to test standard components on both releases and allow automatic adaptation; I found no Apple document or WWDC session describing a supported user preference that toggles between the two macOS sidebar designs. [WWDC26 Modernize your AppKit app](https://developer.apple.com/videos/play/wwdc2026/289/), [Apple sidebar HIG](https://developer.apple.com/design/human-interface-guidelines/sidebars)
